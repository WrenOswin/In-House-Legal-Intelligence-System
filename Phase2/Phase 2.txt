Legal Named Entity Recognition (L-NER) - 7 to 11 Oct 2026 (deadline 11 Oct 23:59 IST)


==========================================================================================
PHASE 2 SUMMARY - character-span legal NER, 12 labels, strict macro-F1
==========================================================================================
Task: predict [start_char, end_char, LABEL] per entity; exact start+end+label match only.
Rules: start from the Phase-1 models (ALL FOUR architectures); >= 4 substantially different
experiments: >= 3 different fine-tuning/PEFT techniques (LoRMA compulsory) + >= 1 knowledge
distillation. Minimum 4 valid submissions (older text in the doc still says 6 - aim for 6+).
Plan: Phase2_Plan.md. Hardware: same laptop (RTX 5070 Ti 12 GB), .venv kernel.

1. EXPERIMENTS
------------------------------------------------------------------------------------------
  E1  A d768 (140.2M)       full fine-tuning + CRF     (teacher for E6)
  E2  A d768                LoRMA+ (multiplicative low-rank, Bihany/Patel/Modi 2025)
  E3  B encoder (~41M)      LoRA

4. OBSERVATIONS
------------------------------------------------------------------------------------------
1. Macro-F1 weights WIT (187 mentions, 12 docs) as much as DATE (1,575, all 70 docs):
   rare classes drive the score -> class balancing is worth testing.

2. Party/counsel/judge entities sit in the header (median position 0.15-0.27 of the doc),
   PREC/AUTH later (~0.55). The first window of each doc holds most APP/RESP/COUNSEL/JUDGE.

3. Same string, different labels (23 surface forms), e.g. "Union of India": RESP 28, APP 14,
   PREC 4, AUTH 4; "Supreme Court": COURT 114, PREC 3; "Central Government": AUTH 64, PREC 2.
   The label depends on context -> a gazetteer/string-match approach cannot work alone.

4. CORRECTED 2026-10-09: annotation is fully consistent within a document. The first count (~10% of repeats
   unannotated) also counted repeats inside larger entities and inside other words. Counting only standalone
   whole-word repeats in the 56 training docs: every repeat of an annotated string is annotated, with the
   same label, for all 12 labels (0 exceptions). -> used for name propagation (observation 24).

5. Token alignment with the Phase-1 BPE: only 1 entity start and 152 ends (of 8,393) fall inside
   a token. Most are punctuation glued by the pre-tokenizer ("SCC 47]." / "1063);" - the entity
   ends before "." or ";"); a few cut inside a word ("Railway Board|s", "Constitutional Ame|ndment").
   Fix: split punctuation runs into single characters for NER; remaining ceiling ~0.3%.

7. Strong overfitting: train loss reaches ~0.001 within ~10 epochs while val F1 plateaus at 0.45-0.50
   (70 docs only). Val F1 jumps +-0.03 between epochs (14 val docs) -> small differences are noise.

8. Keeping the CAUSAL mask works better than removing it for A (0.505 vs 0.473): the representations
   transfer best in the attention mode they were pretrained with.

9. LoRMA with 1.4% trainable parameters matches bidirectional full fine-tuning (0.480 vs 0.473).

10. APP/RESP are the worst labels (F1 0.05-0.16): the model finds the party names but gives every
    mention in a doc the same wrong side - the role is only stated in the header ("... Appellant
    Versus ... Respondent"), which mid-document windows cannot see. -> header-context windows
    (doc's first 256 tokens prepended to every window), running now.

11. Header context did not help (E1 0.492 vs 0.505, LoRMA 0.487 vs 0.507 without it): within val noise,
    APP/RESP stayed weak. Dropped.

12. Causal attention is better for every causal-pretrained model: LoRMA 0.507 vs 0.480, D 0.461 vs 0.427.
    With causal attention LoRMA (1.4% trainable) matches full fine-tuning (0.507 vs 0.505).

13. Codabench vs local validation: E1 (bidirectional full FT, 8fcd22) val 0.4728 -> test 0.4807 (+0.008).
    The 14-doc validation set tracks the test score closely for this run.
    E1 causal (5c4900): val 0.5048 -> test 0.4790. On the test set causal and bidirectional full fine-tuning
    TIE (0.4790 vs 0.4807): the +0.03 causal advantage on validation was noise from the small val set.
    -> differences below ~0.03 on the 14 val docs should not be trusted.

15. LoRMA beats full fine-tuning on the test set: 0.5090 vs 0.4790/0.4807, training 1.4% of the parameters
    (1.9M vs 140.2M). With only 56 training docs, freezing the backbone limits overfitting; the
    parameter-efficient method is not just close to full fine-tuning, it is better. Val 0.5074 -> test 0.5090.

16. Retraining LoRMA on all 70 docs did NOT help: 0.4877 vs 0.5090 with 56 docs. Likely causes: (a) the
    learning-rate schedule changed - the 56-doc run peaked at epoch 5 of a 25-epoch schedule (LR still high),
    the 70-doc run decayed the LR to zero within 6 epochs, so it is not the same model with more data;
    (b) run-to-run variance (seed, which epoch is best) on a 35-doc test set is about +-0.02.
    The 56-doc LoRMA model (684310) stays the final Phase-2 model.

17. Phase-1 ranking carries over to NER (best Codabench per architecture):
    A 0.5090 (LoRMA) > D 0.4628 (partial FT) > C 0.4019 (adapters) > B 0.3631 (LoRA)
    = the Phase-1 ranking A > D > C > B. Better legal LM pretraining -> better NER.
    (Caveat: each architecture used a different method; A shows the method effect is ~0.03, smaller
    than the architecture gaps of 0.05-0.15.)

18. KD on the test set: the 58M student scores 0.4684 vs the 140M teacher's 0.4790 -> 98% of the teacher's
    score with 41% of the parameters. (The student-alone baseline was not uploaded; on validation KD added
    +0.026.)

19. Validation vs Codabench (7 uploads with a val score): test - val = -0.026 to +0.043, mean +0.003; the ranking of
    experiments is largely preserved - only pairs closer than 0.03 swap (E1 causal/bidir, E6/E1 bidir).
    The 14-doc split is a usable but noisy (+-0.03) guide.

20. Word-boundary snapping (found in the error analysis, 2026-10-09): 4.5% of the best model's predictions
    start or end inside a word ('Th' + 'ukral' for 'Thukral', 'OF 200' for 'OF 2008') against 36 of 1,628
    gold val entities. Extending predictions to whole words (and merging overlaps) raises val macro-F1 for
    EVERY model: +0.005 (C) to +0.017 (B); best model 0.5074 -> 0.5185.
    Costs 0.007 on the gold round trip (0.9944 -> 0.9875; the few gold spans that end inside a word).
    Now part of decoding (ner_data.snap_to_words).
    Confirmed on Codabench: the same LoRMA model goes 0.5090 -> 0.5174 (+0.0084) with snapping only.

21. Error analysis of the best model (details: analysis\error_analysis\error_analysis.md):
    - AUTH causes most false positives (333 of 666): generic words ('Government', 'State', 'Board') and
      acronyms ('AICTE', 'VESCO') tagged everywhere, while the gold marks them only in some contexts.
    - Boundary errors: 196 too short (sub-word fragments), 121 too long (modifiers such as 'Delhi High Court'
      vs gold 'High Court', trailing punctuation), 7 shifted.
    - Wrong-label errors are rare (89) and are role confusions: RESP->APP 22, R.COUNSEL->A.COUNSEL 13,
      PREC->COURT 13.
    - APP/RESP: three failure modes - whole-document side flip (1236969: 16 of 23 RESP labelled APP), mixed
      sides (154395703), and missed 'M/s. ...' company names (952082).
    - No clear effect of position in the document (recall 0.59-0.69 in every fifth); weak length effect.
    - LoRMA wins on recall (macro-R 0.577 vs P 0.462): macro-F1 rewards recall on the rare labels.

22. Ensemble (E7, 2026-10-09): averaging the per-token tag probabilities of the three A d768 runs (E2 LoRMA,
    E1 bidir, E1 causal; same tokenizer) before decoding. No training. Val (all with word snapping):
      E2 alone 0.5185 | E2+E1b 0.5534 | E2+E1c 0.5595 | E1b+E1c 0.5467 | all three 0.5594 (micro 0.6337).
    +0.04 macro / +0.07 micro over the best single model - well above val noise. The models make different
    mistakes (LoRMA recall-heavy, full FT balanced), so averaging raises precision without losing recall.

23. Party-role rules (postprocess.resolve_party_roles): APP/RESP predictions in the case title are set by their
    side of 'Versus'/'Vs.'; later APP/RESP predictions matching header names of one side follow it. Designed
    and checked on the TRAINING docs only (clean gold: 622/623 labels kept; 50% random side flips: 50% -> 75%
    correct). Val: ensemble 0.5594 -> 0.5622 (+0.003, APP 0.26->0.28, RESP 0.20->0.23). Small, because side
    flips are not the main APP/RESP problem: the ensemble MISSES 97 of 165 gold APP/RESP mentions entirely.

24. Name propagation (postprocess.propagate_strings, labels APP/RESP/A.COUNSEL/R.COUNSEL/JUDGE/WIT): every
    standalone repeat of a predicted name gets its majority label (justified by observation 4). Val:
      ensemble + roles 0.5622 -> + propagation of names 0.5891 (micro 0.6349 -> 0.6392).
    Propagating ALL labels gave 0.5781 but lowered micro (0.6081): generic strings ('High Court', 'Act') often
    sit inside a larger entity the model did not predict (COURT fp 49 -> 105). The name-only subset was chosen
    AFTER seeing val -> only the Codabench score is an unbiased check. Propagation does not help the single
    LoRMA model (0.5219 -> 0.5206): it spreads that model's false positives, the ensemble is more precise.
    Codabench: 0.5590 (+0.042 over the best single model, 0.5174). Val overestimated this pipeline by 0.030,
    the largest val->test drop so far - consistent with the post-processing choices tuned on val.

25. Where the final gain comes from (Codabench, same LoRMA model throughout):
      LoRMA alone 0.5090 -> + word snapping 0.5174 (+0.008) -> ensemble of 3 + party roles 0.5535 (+0.036)
      -> + name propagation 0.5590 (+0.006).
    The ensemble is the big, reliable step (val predicted +0.044, test +0.036). Name propagation added
    +0.027 on val but only +0.006 on test: most of its val gain was fitting the val docs (the label subset was
    chosen after seeing val). Ensemble-only val 0.5622 -> test 0.5535 (-0.009) vs propagation -0.030.

14. Knowledge distillation works: the 58M student gains +0.026 macro-F1 (0.451 -> 0.477) from the teacher's
    soft labels and recovers ~half of the gap to the 140M teacher (0.505) with 2.4x fewer parameters and
    27% less training memory. It needed more epochs (11 vs 5) - the soft targets act as a regulariser
    against the fast overfitting seen in every run. Inference time on the 14 val docs is the same
    (~3 s): it is dominated by CPU-side decoding (Viterbi in numpy), not by the model.

6. PREC spans are long (median 31 chars, up to 52 tokens) -> BIO tagging rather than span
   enumeration with a small max width.
